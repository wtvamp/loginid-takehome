Software architecture

What runs in the namespace

Two Go binaries built into three images. The API service runs twice: once as an OAuth2 token issuer that alone mounts the signing key, once as a verifier that only ever sees the public JWKS. Every application secret arrives from Vault as a file in memory; none is a Kubernetes Secret. Each workload has its own identity, and default-deny network policies name who may talk to whom.

Q1 · Data access

DAO for user_profile and user_credential

One Repository interface, three backends (Postgres, CockroachDB, SQLite). A conformance suite runs the same assertions against real containers of all three in CI, including CockroachDB's serialization-retry path. Sentinel errors by SQLSTATE, never by message text.

Q2 · REST + auth

Search and retrieve, secured

OAuth2 client credentials mint RS256 tokens with per-client audiences; the verifier checks issuer, audience, and JWKS with bounded staleness. Search returns masked PII; full reads need read:own or read:any with a closed reason-code enum. Scope and policy denials return byte-identical 403s.

Q3 · IDP connector

/auth and /identity to a vendor

Vendor tokens are fetched, used once, and discarded; never cached. Failures take uniform time. Per-identity and overflow-bucket backoff; the failure-ratio limiter fired live during review. Reachable only from api-service by NetworkPolicy.

What the record shows

Six patterns the day kept repeating

The code is the smaller artifact. These are the failure shapes that recurred, each caught by a review step and each closed with a check that makes it fail in CI or at startup instead of in production.

Config named, never set

Three times a binary read an environment variable no manifest set: issuer and audience, the JWKS port, the connector's entire auth. Now every mode declares its required variables in code, refuses to start without them, and a CI test diffs the manifests against that list.

A pattern not carried forward

Five times a control established for one component was missing on a structurally identical new one: NetworkPolicy allow-lists, Forbid on a CronJob, a ServiceAccount per workload. Each got a test that ties the new component to the rule.

Verification that skips

CI was green for hours while every Postgres and CockroachDB test silently skipped for want of a DSN. The fixtures now fail under CI, and the containers are always present.

The detector can fail too

The rule "diff against origin before declaring done" returned a false clean for untracked files, the case most likely to be lost. Five artifacts stranded; the rule now treats a ?? line as unshipped work.

Arithmetic outlives its assumption

An alert threshold of window-plus-one-interval would have fired on every healthy cycle; a rolling-day skip rate was meaningless at a daily schedule. Both were rewritten as functions of one interval constant.

Fail loud, always

Two independent retry loops in Vault Agent; one exits on failure, the other retried forever and hung a pod in Init for seven minutes. The product owner's forced-failure test found it, and now the pod crash-loops in thirty-six seconds.
