    What it looks like

    The live demo console

    Pulled as the forty-third story after the backlog closed, with one requirement added by the human: "make sure it looks good." A single page embedded in the API binary and served at /demo from the same origin, so it carries no secret and needs no CORS. You paste a QA credential that lives only in the tab; the page mints a real token and drives the real endpoints, showing each request as a curl line beside the raw response. These are the product owner's screenshots from her live review.

    The review also recorded one honest limitation: the page sets every autofill hint the platform offers, and a browser-extension password manager still offered to save the QA credential, because extensions use their own heuristics. The control that holds is that the credentials are single-scope, low-value, and revocable by runbook.

    Software architecture

    What runs in the namespace

    Two Go binaries in three images. Watch the requests: a client mints a token at the issuer, calls the verifier, which checks the JWKS in-cluster and reads Postgres; the verifier alone may reach the connector; Vault feeds every pod its secrets at start. Hover a node for what it does.

    client requestJWKS / Vaultdatabasedenied by NetworkPolicy

    Q1 · Data access

    DAO for user_profile and user_credential

    One Repository interface, three backends. A conformance suite runs identical assertions against real Postgres, CockroachDB, and SQLite containers in CI, including CockroachDB's serialization retry. Errors by SQLSTATE, never by message text.

    Q2 · REST + auth

    Search and retrieve, secured

    OAuth2 client credentials mint RS256 tokens with per-client audiences; the verifier checks issuer, audience, and JWKS with bounded staleness. Masked search; full reads need read:own or read:any with a closed reason code; scope and policy denials are byte-identical 403s.

    Q3 · IDP connector

    /auth and /identity to a vendor

    Vendor tokens fetched, used once, discarded. Uniform-timing failures, per-identity and overflow backoff; the failure-ratio limiter fired live in review. Reachable only from api-service.

    What the record shows

    Six patterns the day kept repeating

    Each caught by a review step, each closed with a check that fails in CI or at startup instead of in production.

    Config named, never set

    Three times a binary read an environment variable no manifest set. Now every mode declares its required variables, refuses to start without them, and CI diffs manifests against that list.

    A pattern not carried forward

    Five times a control on one component was missing on an identical new one: NetworkPolicy allow-lists, Forbid on a CronJob, a ServiceAccount per workload. Each got a test tying the new component to the rule.

    Verification that skips

    CI was green for hours while every Postgres and CockroachDB test silently skipped. Fixtures now fail under CI and the containers are always present.

    The detector can fail too

    "Diff against origin before declaring done" returned a false clean for untracked files. Five artifacts stranded; a ?? line is now unshipped work.

    Arithmetic outlives its assumption

    An alert at window-plus-one-interval fired on every healthy cycle; a rolling-day skip rate was meaningless at a daily schedule. Both became functions of one interval constant.

    Fail loud, always

    Vault Agent has two retry loops; one exits, the other retried forever and hung a pod in Init for seven minutes. The forced-failure test found it; the pod now crash-loops in thirty-six seconds.
