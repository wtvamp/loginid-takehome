## Two real corrections from Desmond's claims check on the original four-item spot-check

**1. The same-PR fake-update rule is genuinely not visible anywhere a reviewer would see it — a confirmed, unresolved gap, not a "probably fine."** Desmond checked both the local project and the actual cloned repo: no `CONTRIBUTING.md`, no `pull_request_template.md`, anywhere. `decisions/test-double-strategy.md`'s "added as a stated review-checklist item" is aspirational language with no checklist artifact behind it. **Fix needed:** add a PR template (`.github/pull_request_template.md`) with this as a literal checklist line, or add it to a `CONTRIBUTING.md` — either way, something a reviewer actually sees when opening a PR, not only a design doc nobody re-reads per-PR.

**2. The no-cache-reuse criterion described a mechanism this codebase doesn't have — reworded to match reality, not searched for further.** Desmond read `internal/connector`'s handlers directly: `/identity` takes the vendor token from the caller-presented request header and passes it straight to `FetchIdentity` — it never calls `/auth` internally at all (that's `api-service`'s job, per LT-33). So "a second `/identity` call re-fetches via `/auth`" describes a caller-driven-refetch model this design doesn't use; the real guarantee (proven by `TestStubVendorClient_DistinctTokensPerAuthenticateCall`, `TestHTTPVendorClient_FetchIdentity_FreshAuthorizationHeaderPerRequest`, and the structural absence of any cache field in `Deps`) is that no token-caching field or map exists anywhere in the package, and `/identity`'s token comes solely from the per-request header, never stored state. Criterion reworded accordingly — this is a documentation correction, not a code gap.

**Revised story status: NOT Done.** Finding 1 is a real, unmet criterion — reported prematurely as closed before this check landed. Holding until the PR-template/CONTRIBUTING fix lands.
