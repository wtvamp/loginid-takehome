## Acceptance criteria (restated from `backlog.md` S2)

- [ ] A hire or reviewer unfamiliar with 05's reasoning can implement a backend against this package without re-reading `multi-db-strategy.md` — the Go types here are the contract, not a paraphrase of it.
- [ ] Every sentinel in 05's §4 is defined verbatim (name and wrapped message), including `ErrAlreadyExists`'s status as an internal-error signal with no caller-reachable path. Enforcement site: `dao` package source, doc comment on `ErrAlreadyExists` stating that status explicitly (per Oren's finding #1, ruled by 05).
- [ ] `CreateProfileWithCredential(ctx, p, c)` exists on the composite per 05's §3b resolution, with `c.UserID` ignored on input. Enforcement site: method signature plus a unit test asserting the input `UserID` is overwritten.
- [ ] Pointer fields follow "absent, never empty" — a non-nil, empty `*string` is rejected as `ErrInvalidArgument` at the boundary, not silently accepted. Enforcement site: input-validation unit test per field.
- [ ] (Added for this refinement, the seam-13 mechanical check team-lead named) Every exported type, method signature, and sentinel error name/message in this package matches `05-data-ops/multi-db-strategy.md`'s Go-shaped contract **byte-for-byte** — not "equivalent," not "close enough." Scope, corrected after claims check: the `Repository` composite/factory is §1, domain types are §2, the three sub-interfaces plus `ProfileQuery` are §3, sentinels are §4 — the conformance test must cover all four sections, not §3 alone. Enforcement site: a conformance test (Oren's) that fails on any drift, run in CI on the public repo.
- [ ] The conformance test's source states, in a comment, which of two mechanisms it uses — (a) live-parses expected signatures from `multi-db-strategy.md` §1–§4 at test time, or (b) embeds a frozen copy of the expected signatures written once at scoping time. If (b), the test must also embed a checksum of the source `multi-db-strategy.md` §1–§4 sections it was derived from and fail loudly (not silently pass) if that checksum no longer matches the doc's current content — so a later revision to 05's contract forces a human to re-sync the frozen copy, rather than leaving a conformance test that still runs but no longer means anything. Enforcement site: the doc comment plus the checksum-mismatch failure path in the test itself.

## Research team review

**Desmond Okafor — claims check:** One substantive error found: every reference to "05's §3" as the conformance test's scope was wrong — the `Repository` composite/factory is actually §1, domain types §2, sentinels §4; only the sub-interfaces and `ProfileQuery` are in §3. As written, a test scoped literally to "§3" would miss the composite, domain types, and every sentinel — exactly what the acceptance criteria elsewhere require it to check. Fixed by changing every scope reference to §1–§4. Everything else (the `CreateProfileWithCredential`/`c.UserID` criterion, sentinel count and names, `ErrAlreadyExists` status, and the doc-comment-vs-CI distinction I'd asked about) checked out against `multi-db-strategy.md` and 05's own clarifications.

**Tobias Lindqvist — objection:** The conformance test's durability was left implicit — "byte-for-byte" reads as a solved, stable check, but a live-doc-parsing implementation and a frozen-copy implementation have opposite failure modes (one breaks CI on unrelated prose edits, the other silently stops meaning anything once 05 revises the contract), and neither is visible in the original PO review script. Counter-proposal accepted: the conformance test must declare its mechanism in a comment, and if frozen-copy, must carry a checksum of the source section and fail loudly on drift rather than passing forever.

**Naomi Voss — ruling:** Both fixes applied. This refinement is accepted and ready to hand off — the §1–§4 scope correction is a real fix (an implementer following the original text would have under-built the conformance test), and the mechanism-declaration/checksum requirement closes a durability gap that wouldn't have surfaced until 05 revised the contract later, by which point it would have been much harder to trace.
