## What is SQLSTATE 40001?

Error code 40001 indicates that a transaction failed because it conflicted with another concurrent or recent transaction accessing the same data. All transaction retry errors use the SQLSTATE error code 40001, and emit error messages with the string "restart transaction".

## Client-Side Retry Logic

The transaction needs to be retried by the client. Your code should attempt to execute the transaction. If an error is returned that doesn't have the code 40001, or if the number of transaction retries has exceeded the maximum allowable number of retries, an error should be returned. Otherwise, the system should simply wait a moment (backoff) and try the transaction again.

## Advanced Client-Side Transaction Retries

If a statement returns a retry error (identified via the 40001 error code or "restart transaction" string at the start of the error message), you can issue the ROLLBACK TO SAVEPOINT statement to restart the transaction. A savepoint defined with the name cockroach_restart is a "retry savepoint" and is used to implement advanced client-side transaction retries.

## Language-Specific Libraries

Go developers using GORM or pgx can use the github.com/cockroachdb/cockroach-go/crdb package. Additionally, Python developers using SQLAlchemy can use the sqlalchemy-cockroachdb adapter, and Ruby (Active Record) developers can use the activerecord-cockroachdb-adapter.

Based on the search results, here's what I found about CockroachDB's isolation levels:

## Default Isolation Level

By default, CockroachDB executes all transactions at the strongest ANSI transaction isolation level: SERIALIZABLE, which permits no concurrency anomalies.

## Supported Isolation Levels

CockroachDB offers two transaction isolation levels: SERIALIZABLE and READ COMMITTED. Since v23.2, CockroachDB also supports Read Committed for PostgreSQL migration compatibility (requires an enterprise license from v24.1), but Serializable remains the default.

## Key Differences

READ COMMITTED isolation can prevent many retry errors, because it allows earlier non-locking SELECT statements to be disregarded: even if the current statement needs to be retried, in READ COMMITTED we never need to go back and retry older statements and can generally handle everything on the server side without returning an error to the client.

So to summarize: SERIALIZABLE is CockroachDB's default isolation level, but READ COMMITTED is now available as an alternative option for improved migration compatibility with systems like PostgreSQL that default to READ COMMITTED.
