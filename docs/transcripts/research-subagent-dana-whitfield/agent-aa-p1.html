## Overview

Context engineering has become a prominent term in applied AI, replacing prompt engineering as the focus of attention. Anthropic views context engineering as the natural progression of prompt engineering and refers to it as the set of strategies for curating and maintaining the optimal set of tokens (information) during LLM inference.

## Key Concepts

Context is a critical but finite resource for AI agents. Building with language models is becoming less about finding the right words and phrases for your prompts, and more about answering the broader question of "what configuration of context is most likely to generate our model's desired behavior?"

As agents move from one-shot tasks to multi-turn, long-horizon work, the challenge shifts from "how to write a good prompt" to "what configuration of context is most likely to generate the desired behavior at each step."

## Core Challenge

The core constraint is that LLMs have a finite attention budget, as the transformer architecture creates n² pairwise relationships for n tokens, and as context grows, the model's ability to capture these relationships gets stretched thin.

Anthropic has published comprehensive resources on this topic, including detailed guides and practical implementations for managing context in long-running AI agents.

## Cache Breakpoints Overview

You can define up to 4 cache breakpoints in your prompt. Each breakpoint checkpoints the prefix at that position, and you can use all four: one after the system prompt, one after tool definitions, one after a retrieved document, and one after few-shot examples.

## Best Practices

Place cached content at the beginning of your prompt for optimal performance and use cache breakpoints strategically to separate different cacheable sections. Cache stable, reusable content like system instructions and background information.

You can use just one cache breakpoint at the end of your static content, and the system will automatically find the longest matching prefix.

## Cache Duration

The cache has a 5-minute lifetime (TTL), which is refreshed each time the cached content is used. If you find that 5 minutes is too short, Anthropic also offers a 1-hour cache duration at additional cost.

## Cache Invalidation

Changes to tool_choice or the presence/absence of images anywhere in the prompt will invalidate the cache, requiring a new cache entry to be created.

For the official Anthropic documentation, you can refer to the [Claude Platform Docs on Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

## What are Claude Code Subagents?

Subagents are "specialized AI assistants that handle specific types of tasks. Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions."

## File Locations

Custom subagents live as markdown files in .claude/agents/ (project-level, shared with the team) or ~/.claude/agents/ (user-level, available across all projects).

## Creating Subagents

You can create Claude Code subagents either from the /agents UI or by writing Markdown files with YAML frontmatter. In practice you create a subagent definition by dropping a markdown file into .claude/agents/ with frontmatter for name, description, tools, model, and a system-prompt body.

## Key Configuration Elements

Each one gets its own system prompt, tool permissions, and optionally its own model. The main things to get right are scope, description, tool access, permission mode, and prompt design.

## Benefits

When the main agent delegates a task to a subagent, the subagent runs independently, does its work, and returns only its final output to the parent. All the intermediate noise — the file reads, the search results, the exploratory tool calls — stays inside the subagent's context and never touches the main conversation.

# Context Management for Long-Running Agents

## Core Challenge
LLMs face inherent limitations managing extended interactions. The article identifies "context pollution and information relevance concerns" that persist regardless of window size.

## Key Recommendations

**1. Compaction**
Summarize conversation history when approaching context limits, then restart with a condensed summary. The approach "distills the contents of a context window in a high-fidelity manner, enabling the agent to continue with minimal performance degradation." Start by maximizing recall, then improve precision by removing redundant content like old tool outputs.

**2. Structured Note-Taking**
Agents maintain persistent memory outside the context window through files or dedicated memory systems. This allows tracking progress across complex tasks without consuming immediate context space.

**3. Sub-Agent Architectures**
Specialized agents handle focused tasks with clean context windows while reporting condensed summaries (typically 1,000-2,000 tokens) to a coordinating agent. This separates detailed exploration work from high-level synthesis.

**4. Just-in-Time Retrieval**
Rather than pre-loading all data, agents use tools to dynamically retrieve references (file paths, queries, links) at runtime. This mirrors human cognition—maintaining lightweight identifiers instead of exhaustive information.

**5. Hybrid Approach**
Combine upfront retrieval for speed with autonomous exploration at the agent's discretion, suited to the specific task requirements.

The overarching principle: "find the smallest set of high-signal tokens that maximize the likelihood of your desired outcome."
