Findings, in order of the four questions: **1. `retention_sweep_skipped_total` is a name that never gets implemented — real drift, same class as the nine/eleven item.** The original 04-side acceptance criterion (line 28) and the original alert-rule text (line 29) both name it as a gauge `api-service` must serve, and the alert `RetentionSweepSkipRate` is described as keying on its rate. But Priya's ruling (lines 145–157) and Renata's implementation update (lines 159–169) both supersede this: the skip signal ends up as `missed_slots`, computed from the persisted `retention_sweep_run` table, and `RetentionSweepSkipRate` becomes `sum(missed_slots)` over a rolling day — nowhere does either implementation emit a metric literally named `retention_sweep_skipped_total`. The two earlier bullets that name it were never struck or corrected once the table-based approach replaced it. Fix: amend lines 28–29 to remove `retention_sweep_skipped_total` and replace with "skip-rate derived from `missed_slots` per the `retention_sweep_run` table (§145–157)," the same way the nine→eleven drift got a named correction rather than being left to contradict itself silently. **2. "Same underlying decision" (LT-20 line 23) is asserted, not ruled, by someone with actual authority over either half.** Amber's inventory treats RBAC-scoping (§3c, `handoff-amber-observability-inventory.md`) and retention/ILM-scoping (§3, dedicated-stream option) as two separate consequences of the same Basic-license constraint — not as one decision. Nobody who owns the audit-log design (Marcus, 02) or the `logging`/Elastic side has confirmed that a stream created to solve RBAC-scoping also satisfies whatever retention window 05 rules. Concrete risk: if Option A ships to close LT-49's RBAC item, LT-20 could get marked Done by proxy — "the stream exists, so retention is handled" — without anyone separately checking that the ILM policy applied to that stream actually matches the ruled window, or that it was applied at all. Counter-proposal: LT-20's Done criteria should require the ILM policy be independently confirmed against the dedicated stream by name, even if Option A is adopted jointly — a shared *stream* is not a shared *closed loop*. **3. PO-script step 9 doesn't say which `class` label the throwaway rule should target, and using a real one is the wrong default.** If the throwaway `RetentionWindowExceeded` override targets an existing production class (e.g. `direct`), for the duration of the test it reports a real customer-data class as window-exceeded — a false signal any dashboard or downstream consumer watching that label sees as real, and it muddies "did it fire, did it clear" if someone else is also watching that class. Fix: step 9 should specify a reserved/synthetic class label (e.g. `class="_test_"`) never used by real sweep data, so the fire-and-clear check is unambiguous and doesn't transiently report a false alarm on real data.
