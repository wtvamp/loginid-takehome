## The catch list

Each item found a genuine cross-backend divergence invisible from reading either implementation in isolation — the exact failure mode §7 says the suite exists to catch.

- **Identifier validation (Amendment A4, §3a/§4/§7)** — `Get` with a malformed id diverged by backend: Postgres/CockroachDB raise `22P02` before any lookup (`id` is `UUID`-typed), SQLite returns `ErrNotFound` (`id` is `TEXT`). Ruled: malformed *or non-canonical* ids return `ErrInvalidArgument`, validated once above the backends against the canonical form only. Went through an objection round (Yusuf Karadag, five objections, all accepted) after the first validator moved the divergence rather than closing it — `uuid.Parse` admits textual forms Postgres normalizes and SQLite byte-compares and misses.
- **COLLATE "C" invalid on CockroachDB (Amendment A5, §5/§6.3/§6.9)** — the shared `postgres/` migration directory's `COLLATE "C"` clause is invalid syntax on CockroachDB (`42601`); CockroachDB's default `TEXT` comparison is already byte-order and needs no clause. Blocked the CockroachDB conformance run outright until the migration directories were split three ways, one per driver. Verified directly against live CockroachDB v23.2.0, including the empirical check that its uncollated default already gives the required ordering.
- **SQLite `foreign_keys` pragma is per-connection (Amendment A3, §6.2/§7)** — `PRAGMA foreign_keys = ON` run once after opening only covered the connection that ran it; the cascade guarantee and `ErrInvalidMethod` FK enforcement silently stopped applying the moment the pool opened a second connection. Fixed via the `_foreign_keys=on` DSN param (applies per-connection by construction), verified by temporarily reverting it and watching `TestIntegration_ProfileDeleteCascadesToCredentials` fail.
- **`requires_secret`/`is_active` enforcement (§6.10, §6.12)** — neither can be a DDL `CHECK` (one needs `is_active` read from `auth_method`, the other needs `requires_secret` read cross-table); both were missing DAO-layer validation before this round. Now enforced in both backends' `CreateProfileWithCredential`/credential-create paths, each with a conformance assertion.
- **`Country` write-side normalization (§6.5)** — upper-casing the query without upper-casing the stored value made a stored `us` invisible to a search for `US`. Fixed at write time in both backends' `NormalizeProfileForWrite`.
- **`DeleteExpired`/`DeleteProfile` TOCTOU (review round, Oren Castellan)** — the original select-then-loop-delete (and select-then-delete) pattern could delete a row that had stopped matching its retention predicate between selection and deletion. Postgres/CockroachDB: collapsed to one CTE-based statement where the `DELETE` re-checks the candidate `SELECT`'s predicate (CockroachDB additionally requires `RETURNING` on every write CTE, or it rejects the statement as returning no columns). SQLite: re-adds the predicate to the per-row `DELETE` directly, since SQLite has no writable-CTE support (confirmed by testing DML inside `WITH` directly: `SQL logic error: near DELETE: syntax error`) — same fix intent, backend-appropriate mechanism.
- **No backoff on CockroachDB retry (review round, Nolan Reyes)** — `retryLoop` retried a `40001` serialization failure in a tight spin loop; added jittered backoff between attempts, with a test confirming a cancelled context aborts the wait rather than blocking for its full duration.
- **Nil-vs-empty-slice JSON serialization (review round, Oren Castellan)** — `Search`/`ListByUserID`/`List` returned a nil slice on zero results, serializing to `null` instead of `[]`; fixed in both backends.
