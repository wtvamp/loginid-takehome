## POSTGRES_PASSWORD_FILE

As an alternative to passing sensitive information via environment variables, _FILE may be appended to some of the previously listed environment variables, causing the initialization script to load the values for those variables from files present in the container. In particular, this can be used to load passwords from Docker secrets stored in /run/secrets/<secret_name> files.

### Supported Variables

Currently, this is only supported for POSTGRES_INITDB_ARGS, POSTGRES_PASSWORD, POSTGRES_USER, and POSTGRES_DB.

### Example Usage

Example: `docker run --name some-postgres -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres-passwd -d postgres`

This approach is particularly useful for securely passing sensitive information like passwords in Docker environments without exposing them as plain-text environment variables.

## concurrencyPolicy: Forbid

When using Forbid, the CronJob does not allow concurrent runs; if it is time for a new Job run and the previous Job run hasn't finished yet, the CronJob skips the new Job run.

## JobAlreadyActive Event

Each skipped tick is logged as a Warning event with reason JobAlreadyActive. The event message states: "Not starting job because prior execution is running and concurrency policy is Forbid".

## How It Works

When a Job takes longer than the schedule interval, it is still active when the next tick fires. Kubernetes prevents job runs from overlapping when the policy is set to Forbid—a scheduled run will be skipped if the previous one is not finished.

## Skipped Runs and startingDeadlineSeconds

Runs that were skipped due to the Forbid concurrency policy will still execute if the previous Job finishes before the new run's startingDeadlineSeconds expires.
